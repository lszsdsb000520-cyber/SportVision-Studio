# 乒乓轨迹 Studio v8.1

Windows 本地视频分析与人工审核软件。小球检测使用 BlurBall，球台识别使用 TT3D 公开模型，轨迹恢复、事件候选、人工标注和审核数据管理由本项目实现。来源与许可证见 SOURCES.md。

## 启动与视频编号

打开项目中的“乒乓轨迹 Studio”快捷方式或 start.cmd。新版程序位于 dist/PingPongStudio-v8.1/PingPongStudio-v8.1.exe，保留整个目录即可运行，无需安装 Python。升级后先保存并关闭旧窗口，再重新启动，窗口标题应显示 v8.1。

v8.1 将摄像头打开、取帧和释放放在独立采集进程中。预览与推理读取最新画面，慢推理时预览仍可更新。采集超时后会切换驱动尝试重连，连续失败会显示错误并释放设备。Windows 两种驱动的摄像头编号可能不同，重连后请核对预览和球台。模拟采集测试覆盖驱动卡死、恢复、停止和重启。真实外接摄像头仍需实拍验证。

v8 将界面分为比赛复盘和实时观测两页。模型参数、角点操作、导出、标注与筛选可按需展开。离线分析自动优先使用独立显卡，解码准备、模型推理和轨迹提取并行。针对 1920×1080 的 YUV420 视频，原生加速模块计算模型真正使用的输入像素，开头逐像素校验，校验不一致时回到常规转换。分析使用原始全部帧和 FP32 模型。

点击「实时监测」，选择视频或内置示例后开始监测。程序先识别球台，然后按原视频时间逐批读取与检测，右侧随画面更新触台、疑似触网和疑似出界。实时模式按算力选择最高 60 FPS 的取样率，界面显示取样间隔。触台候选至少观察约 0.22 秒后续画面，回合终止候选至少约 0.7 秒。自动标定失败时，可在当前画面手动点四角并重启监测。

实拍时选择「Windows 摄像头」。通过「蓝牙配对」打开系统设置，再通过「系统摄像头」确认设备能提供视频流，选择相应设备编号。支持由 Windows 识别为摄像头的设备。仅能配对、未向 Windows 提供摄像头画面的设备无法读取。硬件实拍需要在真实外设上验证。

v7.2 修复长视频和高帧率视频播放卡顿：后台独立解码，最多缓存8个待显示画面；界面按真实时间戳同步显示，不再把逐帧处理耗时累加为慢放。播放预览最高30帧/秒，慢放时按相应时间间隔显示；原始视频、分析轨迹、逐帧标点和导出保留全部原始帧。暂停、跳转与变速会停止旧播放读取器，逐帧定位仍使用原始分辨率。静态二维图不再逐帧重绘，“当前附近”列表在播放时最多每秒刷新4次。旧分析项目可以直接打开，无需重新分析。

v7.1 修复深蓝台面分割残缺导致自动标台失败的问题：严格轮廓校验失败时，仅在模型高置信度区域附近，结合台面颜色与边缘恢复四角，再由独立视频读取器采样附近帧检查一致性。不会消费预览读取器的首帧或删除视频帧。没有可靠边界时明确提示识别未成功，保留视频与已有标定，可以换帧或手动标定；不将不可靠矩形当作识别成功。边界仍需人工核对，尤其在转场、移动机位和遮挡时。

v7 使用随程序提供的 PyAV/FFmpeg 解码器，并保留 OpenCV 备用路径。按实际解码帧数和逐帧时间戳分析、定位与导出，支持可变帧率和旋转信息；不会因视频头部帧数差一帧而丢弃整段结果。对坏包尝试跳过，对明显提前中断尝试备用解码；可读片段不足或发生丢包会提示复核。损坏、加密或缺少必要头信息的视频仍可能无法恢复，不能保证任何文件都可完整解码。导出使用 H.264 MP4，保持源时间轴，不含音频。

v7 将明显横向速度反转的接触优先列为“疑似击球”，不映射为台面落点。V011 第209帧改为疑似击球，第197帧触台保留；这属于轨迹规则推断，仍需人工复核。新增短暂突跳过滤只删除不连贯候选，不凭空补球。旧分析需要重新分析才能应用完整过滤，已确认事件不会被重算覆盖。

视频上方新增“拖动画面”：开启后左键拖动，普通模式放大后远离角点也能左键平移，右键/中键拖动仍可用。取消覆盖分析、导出和数据整理，取消中会显示状态；正在执行的单次原生解码或推理需要返回后才能退出。密集落点编号采用两侧引线并自动增加图表高度，可在右侧滚动查看、点击编号；编号为稳定事件ID，删除、隐藏或其他事件类型可能导致数字不连续。

v6 默认结合候选持续停留和局部图像变化过滤静态背景白点。V009截图位置的11个误检帧在回归中均被移除，原有566帧回归F1未变。真实持球静止时可关闭该过滤或人工修正；旧项目需要重新分析才能应用，不覆盖已有人工标注。

新增“导出二维落点图”和“导出轨迹＋落点同步视频”：右侧按触台帧累计落点，保持源视频帧率与帧数，没有音频；可采用当前隐藏/筛选或仅已确认事件。原作者发布的演示、未叠加标记的输入和原始权重本地复现分别放在 video_raw 的三个子目录，详见该目录README和manifest。

v5 增加交互式落点图：点击编号联动视频与事件列表，重复点击切换重叠点，右键可单独隐藏。事件列表支持状态/类型/半场筛选、编号或帧号搜索、当前前后2秒筛选；Ctrl/Shift多选后可批量隐藏、显示、确认和删除。Alt+H切换所选可见性，Alt+Shift+H恢复全部，Ctrl+Enter确认所选。双击显示列切换隐藏，双击其他列编辑。

事件编号随项目保存，不会因隐藏或删除其他事件重新编号，CSV也包含对应编号。隐藏设置保存到项目，只影响球台图、视频预览及当前图层视频导出；CSV、审核项目和训练事件保持完整，隐藏不代表删除或确认。待复核模式确认后继续下一项；重算为同类且相邻帧的候选保留编号。具体交互验证见 reports/v5。

左侧模型方案可选“通用场景（原模型）”和“侧视比赛（新数据微调）”。本轮基于新增 ExtendedOpenTTGames 标注微调8轮，在432帧保留测试子集上，小球定位F1由95.26%提升到98.07%，漏检26降到1、误检12增到15；仅校准原模型阈值的F1为95.79%。该指标不代表落点或回合结束分类准确率。

旧场景566帧回归中，微调模型F1由95.75%退化至93.42%，因此保留原通用模型作为默认，仅将微调模型作为侧视方案提供。侧视方案自动使用0.30阈值；切换方案后重新分析才会更新预测，已有人工标注不随模型选择改变。详细配置、权重、曲线与比较见 runs/extended-transfer-2026-11-06-152847 和 reports/extended。

v3.4 支持包含首尾帧的不可见区间标注、进度条设起点/终点、最近10次标注撤销（Ctrl+Z）及上一/下一事件跳转（Alt+方向键）。不可见区间默认保留事件，也可明确选择同时删除。视频上方可独立控制轨迹、球心、落点、出界/拦网和球台边界；“纯视频”暂时隐藏全部图层。导出采用当前图层组合，审核入库仍保存原视频，文件名为导入视频名_success.原扩展名。

video 内现有素材使用 V001—V358；两个约 30 秒组合测试视频使用 T01、T02。分类副本沿用相同编号。原名和路径保存在 video/name_map.json，素材信息在 video/catalog.json。现有分析项目及 CSV、片段清单已对应更新；旧项目引用旧视频路径时，v3 可通过映射查找。重命名未改变视频字节和旧 CSV 标签内容。

两个测试视频位于 video/by_duration/00_30s_tests，最新自动分析项目位于该目录的 v3_analysis。视频由多个独立回合组合，保留同名 .segments.json 可让推理和事件拟合在切换处分段。

## 分析与漏检复核

1. 导入视频，自动识别球台后检查绿色边界。四角可拖动微调，也可手动标定或调整台面方向。
2. 开始分析。模型的低置信度候选只有在前后可靠球心、空间距离和运动连续性均支持时才恢复；短时缺失可参与反弹两侧拟合，长缺失和切换处不跨段拟合。
3. 事件包括触台、疑似出界、疑似被网拦下。触台同时输出较严格与优先复核的补检候选；边线附近的模糊情况单独提示。
4. 右侧显示近端和远端触台数量。同侧连续触台会提示检查另一侧是否漏检，点击提示可跳到相应区间。计数用于复核，不强制补齐两侧数量。
5. 出界候选需要观察到离台或越出台面邻域后的持续运动；单纯丢球不直接作为出界。拦网候选结合接近球网、减速或反向、同侧下落及后续轨迹；普通过网不作为拦网。
6. 用“每次 N 帧”、绝对帧号跳转、时间轴或慢放回看。视频和事件区域之间可拖动分隔线调整高度。

这些事件仍是二维视频推断的候选，不是自动裁判结果。遮挡、特殊机位、漏检和球台误差可能导致误判。没有独立人工事件真值前，不报告正式事件准确率或厘米级误差。

## 人工标注

- 修改位置：选中事件，跳到正确帧，点击“点击画面改落点”，再点击实际位置。
- 修改帧号或类型：点击“编辑选中事件”，可改成触台、出界或被网拦下，并输入帧号、画面坐标。
- 补漏检：点击“新增事件”，在画面点选位置，再选择事件类型。
- 删除误检：选择事件后删除。删除记录保留，重算候选时不会自动加回同一事件。
- 修改球心：定位帧后点击“修正球心”，再点实际球心；球不可见时可显式标记“本帧球不可见”。
- 确认、撤销和所有修正均记录在项目中。Esc 可取消尚未完成的点选。
- “重算候选”保留人工修正、已确认事件和删除记录。打开旧项目会升级未确认候选；旧版已确认事件需要人工复核。

人工落点和球心是不同的标注范围：只改落点不会把同帧或整段自动球心预测伪装成球心真值。

## 审核通过与 video_success

完成整段复核后，点击固定在左下方的“审核通过 → video_success”，勾选整段事件及球台已核对的声明后保存。只有人工执行这一操作才会进入审核库。默认根目录为项目下的 video_success。

每次生成一个新审核版本：

- 导入视频名_success.原扩展名：原始输入内容，不是带轨迹的渲染视频；
- project.json：修正后的事件、轨迹、删除记录、编辑历史、审核范围和来源；
- events.csv：人工审核的触台、出界、拦网标签；
- ball_labels.csv：球心标注及 reviewed/unreviewed 状态，单位为原视频像素；
- approved.json：审核版本、文件校验值、尺寸、帧率和来源分组。

未勾选“逐帧核对全部球心及不可见帧”时，球心训练标签仅包含手动修正或显式标为不可见的帧，其余行留为未审核。未审核不等于球不可见。再次修改当前项目会将其标为待重新审核；已入库的历史版本保留。

## 为后续训练准备数据

点击“生成已审核训练清单”，或运行：

    .venv-app/Scripts/python.exe tools/prepare_success_training.py

输出 datasets/reviewed/training_index.json。仅收录已审核版本，按内容校验去重并使用最新审核记录；已修改或损坏的审核文件需要重新审核。同一视频的历史版本、已知配对机位和组合素材按来源组划分，避免直接按相邻帧随机拆分。来源组推断并不替代独立测试来源核验，素材太少时清单会指出缺少验证组。

事件标签与球心标签的审核范围分开保留，便于后续训练相应模型。当前模型不会因为保存一个项目就自动换成新的权重。

## 已完成验证

- 32 项回归检查：V 形和缺失轨迹、低分峰恢复、过网与拦网区别、出界与单纯丢球区别、审核声明、版本保存、未知球心标签、校验、旧路径解析、导出和取消等。
- 实际 GUI 流程：事件类型与帧号修改、点击改落点、补充事件、误检删除后重算、人工球心修正、模拟审核保存及训练清单。
- 模拟审核仅写入 work/qa-v3 和自检目录，不代表用户审核，也没有向实际 video_success 放入假审核数据。
- T01/T02 全片推理完成，触台候选从 v2 的 37/43 增至 47/48。新增候选仍需复核，数量增加不是准确率结论。
- 出界/拦网规则经过构造轨迹检查，尚缺足够的独立真人事件标签评估其精度。
- 独立 EXE 自检证据和实际性能见 reports/v3；速度随素材与负载变化。

## 开发

运行 .venv/Scripts/python.exe -m pytest -q 进行回归检查，tools/verify_v3.py 验证 GUI 审核流程，tools/verify_long_v3.py 分析 T01/T02，tools/build.py 打包 v3。训练和运行环境分开；依赖见 requirements 文件。原始 TTNet 下载目录未改动，旧 CSV 的时间对齐问题未因重命名得到修复，不作为新审核标签使用。
