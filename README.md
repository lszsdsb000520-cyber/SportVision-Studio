# SportVision Studio · 乒乓轨迹分析与篮球球员跟踪

中南大学计算机学院课程实践与比赛项目。提供乒乓球视频复盘、轨迹展示、触台候选复核和人工标注，同时保留篮球球员跟踪的比赛接口实现。

## 可以做什么

- 导入乒乓球视频，自动定位球台、检测小球并绘制轨迹。
- 在二维球台上查看落点编号，点击落点跳转视频，筛选或隐藏事件。
- 放大并拖动画面，逐帧或按指定帧数跳转，修正球心、落点和不可见区间。
- 导出二维落点图、带轨迹的视频、轨迹与落点同步视频以及 CSV/JSON。
- 审核后保存到 `video_success`，为后续训练整理人工确认的数据。
- 在固定机位下使用视频模拟实时检测，或读取 Windows 摄像头画面。
- 比赛工程输出篮球球员检测框与轨迹编号，包含场内球员筛选和跨帧关联。

篮球入口位于 `competition/participant/basketball`，桌面界面当前主要服务于乒乓球复盘。摄像头传输经过模拟测试，外接硬件的稳定性需要实拍核验。触台、触网和出界均需结合视频人工复核。

## Windows 源码启动

建议使用 Python 3.11，在仓库根目录打开 PowerShell。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime.txt
.\.venv\Scripts\python.exe app.py
```

也可在创建环境并安装依赖后双击 `start.cmd`。正常启动后会出现中文桌面窗口。模型位于 `models`，无需下载整个 Docker 镜像。首次使用导入自己的视频，检查自动球台边界，开始分析后逐项复核事件，再导出结果。

运行依赖按原项目环境固定，详见 `requirements-runtime.txt`。DirectML 用于 Windows GPU 推理，其他环境需自行配置相应的 ONNX Runtime 后端。训练环境单独使用 `requirements-training.txt`。

## 比赛工程与篮球运行

`competition` 保留双赛题运行器、两种算法、权重、公开集清单和标注。为控制仓库大小，原始比赛视频、基础环境镜像和提交镜像不在仓库中。请从官方工程包恢复各任务的 `public_data/videos`，路径应与清单一致。

在官方 `sport-base:v1` 环境中，参照 [比赛操作说明](competition/双赛题使用说明.md) 执行。该说明中的目录以 `competition` 为工作目录。若在其他机器重建环境，还需自行取得官方基础镜像。

```bash
cd competition
docker build --pull=false -t sport-vision-submit:latest .
```

本仓库是可继续开发的源码工程。比赛平台使用的是从 Docker 导出的镜像文件，构建步骤见上述说明。

## 已有验证结果

以下为历史 V2 公开集复测，公开集参与过方案比较。乒乓球 15 段、篮球 2 段，共 3,609 帧。

| 指标 | V1 | V2 |
| --- | ---: | ---: |
| 乒乓球落点 F1 | 81.28% | 83.42% |
| 篮球 IDF1 | 49.32% | 55.29% |
| 篮球 MOTA | 63.04% | 73.58% |

同一台电脑使用 DirectML 推理、CPU 解码，历史测得乒乓球 2,109 帧用时 35.1 秒，篮球 1,500 帧用时 29.2 秒，均不含初始化。这些数字不能直接推算其他设备或官方隐藏集成绩。范围和局限见 [验证记录](docs/validation-v2.md)。

## 来源与使用条件

桌面小球检测使用 BlurBall，球台分割使用 TT3D。比赛工程保留官方参考检测器并改进落点判断、球员筛选和关联逻辑。各模型、数据集和第三方库的来源及许可证见 [SOURCES.md](SOURCES.md)、`pingpong/vendor` 和各权重目录。特别是微调数据包含 CC BY-NC-SA 4.0 条件，使用时须核对相应授权。

## 如何验证

在装好桌面运行依赖的环境中安装 pytest 并运行。

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest -q
```

比赛框架检查在官方环境执行，见比赛操作说明。回归测试通过表示所覆盖的流程符合预期，准确率仍需使用独立标注数据评估。
