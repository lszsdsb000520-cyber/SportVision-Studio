# 乒乓球落点检测与篮球球员跟踪

这是比赛测评用的双赛题工程。乒乓球输出每次触台的帧号和画面坐标；篮球逐帧输出球员的位置框和轨迹编号。原来的 Windows 桌面软件可以继续用来人工复核。

## 这次改了什么

- 乒乓球：在多帧画面中定位台面，结合触台前后的速度变化找落点；相邻候选优先保留速度转折更清楚的落点。正面视频保留滑窗，斜侧和侧面视频每次推理处理三帧。检测权重沿用官方参考模型；官方训练数据上的试训权重没有在固定阈值下超过原权重，未放进比赛包。台面分割使用 TT3D 导出权重，来源和许可证在权重目录。
- 篮球：在官方球员检测器上加了两个用官方训练数据拟合的分类器。新版同时考察球员框的大小、位置和脚下地面特征，减少把裁判和场边人员当成球员。用移动方向和球衣特征接续轨迹，结合比分栏和镜头变化排除回放及特写。新版复用每帧的图像处理缓冲，仍默认逐帧检测。

## 在咪咕仝学上自测

1. 解压后，把包里的 `participant` 文件夹放到官方环境的 `/participant`。
2. 用下面命令跑自带的公开验证视频。官方包保留了乒乓球 15 段和篮球 2 段，不需要另外上传训练集。

```bash
cd /participant
mkdir -p input
ln -sfn ../pingpang/public_data input/pingpang
ln -sfn ../basketball/public_data input/basketball
bash run_all.sh input output
```

两个任务各有一个输出目录：`output/pingpang` 和 `output/basketball`。打开 `predictions.jsonl` 看预测，打开 `run_status.json` 看耗时和检查结果；有错误时先看该目录的 `run.log`。正式评测会由平台挂载自己的输入目录。

解压目录里的 `score_public.py` 可以复算公开集准确率。它还会检查运行记录里有没有漏视频、少解码或预测格式错误。在包含 `participant` 的目录中运行，下面以输出在 `participant/output` 为例：

```bash
python score_public.py pingpang participant/output/pingpang/predictions.jsonl --run-status participant/output/pingpang/run_status.json
python score_public.py basketball participant/output/basketball/predictions.jsonl --run-status participant/output/basketball/run_status.json
```

乒乓球会显示各角度的 F1、完全命中标注帧的数量，以及匹配落点的像素误差中位数。篮球会显示 IDF1、MOTA、身份切换次数和没有球员标注时产生的误框数。这里是根据公开规则复算的结果；最终排名以官方隐藏集为准。

## 用 Docker 打包后上传

在有 Docker 和 NVIDIA GPU 容器支持的机器上，在本说明旁边的 `Dockerfile` 所在目录运行。第一行的基础镜像路径按实际位置填写。

```bash
docker load -i /path/to/sport-base_v1.tar
docker build --pull=false -t sport-vision-submit:latest .
mkdir -p review-output
docker run --rm --gpus all --entrypoint /bin/bash \
  -v "$PWD/review-output:/participant/output" sport-vision-submit:latest \
  -lc 'mkdir -p /participant/input && ln -sfn ../pingpang/public_data /participant/input/pingpang && ln -sfn ../basketball/public_data /participant/input/basketball && /participant/run_all.sh /participant/input /participant/output'
docker save sport-vision-submit:latest -o sport-vision-submit.tar
```

上传到比赛页面的文件是最后生成的 `sport-vision-submit.tar`。本工程 ZIP 用来解压和构建镜像，不能当成 Docker 镜像上传。首次运行可能需要在本机生成 TensorRT 缓存；等公开数据跑完、两个任务都通过检查后再提交。

## 结果如何理解

公开验证集可以复现本轮改动，但它不是官方隐藏测试集。公开篮球验证只有一场比赛的两个片段。Windows 上的测试使用本机显卡推理和 CPU 解码，不能当成官方双 4090 环境的速度。基础环境组件无需为本工程升级。
